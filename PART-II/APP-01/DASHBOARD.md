# APP-01 | 브랜드 맞춤형 서울 출점 포트폴리오 대시보드

## 1. 역할

APP-01은 베이커리 프랜차이즈 본사 사업개발팀이 브랜드를 선택하고 희망 출점 수를 지정하면, 그 브랜드의 입점 DNA를 기준으로 이번 분기에 함께 검토할 서울 출점 후보 조합을 확인할 수 있는 웹 대시보드다. 예상 매출이나 성공 확률이 아닌, 브랜드별 기존 입점 환경과의 유사도를 근거로 후보를 비교하는 데 목적이 있다.

**배포 URL**: https://bc-card-consumer-data-2026.onrender.com/

## 2. 화면 구성

README 초기 설계 단계에서는 8단계 화면 순서(선택 → DNA 요약 → 포트폴리오 → 개별 상권 → 점수 구성 → 요인 → 신뢰도 → 검토사항)로 정의했으며, 실제 구현 과정에서 정보 성격에 따라 3개 탭으로 재구성했다. 점수 구성·긍정/위험 요인·데이터 신뢰도·추가 검토사항은 독립된 화면이 아니라 각 상권 카드 안에 자연스럽게 포함되는 정보라고 판단했기 때문이다.

| 탭 | 포함 내용 |
|---|---|
| **Brand Overview** | 브랜드 DNA 요약, 강점/주의사항, 최우선 단일 후보, 조합 1순위 요약, 1순위 상권 적합도 게이지, 미니 지도 |
| **추천 포트폴리오** | 희망 출점 수에 해당하는 Top 3 조합 카드(순위·종합 점수·구성 상권·선정 근거·위험 요인), 조합 간 지표 비교 그래프, 공통 추가 검토사항 |
| **상권 상세** | 지도(전체 후보 상권 마커) + 요약 표, 행 클릭 시 점수 구성 그래프·핵심 특징·강점/위험·데이터 신뢰도·추가 검토사항이 펼쳐짐 |

**APP-01 규칙**

- 상단에 mock 데이터 안내 문구를 항상 고정 표시한다.
- 좋은 점수(적합도, 시장 규모, 분산도 등)와 위험 점수(근접 위험도, 중복 위험)는 항상 다른 색 계열로 표시한다.
- "예상 매출", "성공 확률"로 읽힐 수 있는 표현은 사용하지 않는다.
- 포트폴리오 카드의 상권명, Overview의 미니 지도를 클릭하면 상권 상세 탭의 해당 상권으로 이동한다.

## 3. 사용 데이터 파일

- `result_schema.json` — 모델 결과 JSON 구조 정의 (참조용)
- `mock_recommendations.json` — 화면 개발용 가짜 추천 결과. 실제 MODEL-01 결과로 교체될 예정이며, 교체 시 JSON 구조는 유지하고 값만 바뀐다는 전제로 화면을 설계했다.
- `brand_area_presence.parquet`, `brand_name_mapping.csv` (DATA-01 산출물) — 상권별 경쟁 브랜드 집계 로직(`competitor_lookup.py`)에서 사용. 단, mock 데이터의 `area_id` 체계와 DATA-01의 실제 서울시 상권 코드 체계가 달라 현재 화면에는 연결되지 않은 상태다 (6. 알려진 한계 참고).

## 5. 디자인 원칙

- 베이지·앰버 톤 색상 팔레트, Fraunces(제목) + Inter(본문) 폰트 조합을 프로젝트 전체에 일관 적용했다.
- 적합도 점수는 80점 이상 **매우 적합**(초록), 65~80점 **적합**(머스타드), 65점 미만 **검토 필요**(브릭레드)로 구간을 나눴다. 이 구간은 잠정 기준이며, 실제 점수 분포를 알 수 없는 mock 데이터 단계에서 임의로 정한 값이므로 MODEL-01 결과가 나오면 A와 함께 재검토가 필요하다.
- 순위 표시는 뱃지 대신 큰 숫자(1순위 강조색, 2·3순위 회색조)로 시각적 위계를 표현했다.

## 6. 한계

- **경쟁 브랜드 정보 미연결**: `mock_recommendations.json`의 `area_id`(`"MOCK-A001"` 등)와 DATA-01의 실제 서울시 상권 코드(`"3001491"` 등)가 서로 다른 체계라, 상권별 경쟁 브랜드 목록을 화면에 아직 연결하지 못했다. 집계 로직(`competitor_lookup.py`) 자체는 실제 DATA-01 파일로 검증 완료했으며, MODEL-01이 실제 `area_id` 기준 결과를 내놓으면 그대로 연결 가능하다.
- 프랜차이즈 밀집도(`facts.bakery_franchise_share`), 최근접 점포 거리(`facts.min_distance_to_existing_store_m`) 값은 `mock_recommendations.json`에 화면 개발용으로 채워진 값이며, DATA-02가 실제 값을 산출하면 교체될 예정이다.
- `ui_copy` 필드(브랜드별 화면 문구)를 데이터에서 읽어오지 않고 화면 코드에 직접 작성했다. 문구가 향후 자주 바뀔 가능성이 낮다고 판단해 의도적으로 단순화한 부분이다.
- 지도는 Leaflet + OpenStreetMap을 사용한다. 한국 지도 데이터 정확도를 고려하여 네이버맵, 카카오맵의 연동 또한 고려중이다.
- 브랜드별 접근 통제(로그인, 권한 분리) 없이 모든 브랜드를 자유롭게 조회할 수 있다. 현재는 심사위원이 여러 브랜드를 자유롭게 비교해볼 수 있어야 한다는 목적에 맞춘 의도적인 설계이며, 실제 다수 브랜드 대상 서비스화 시에는 접근 통제가 필요하다.
- Render의 리밋으로 인해 슬립 모드가 실행되면 초기 사이트 오픈 시 로딩 시간이 소요될 수 있다. 이에 따라 UptimeRobot 무료 티어 버전으로 5~10분 간격 핑을 설정해 슬립 모드를 방지하되, 심사 기간에 맞춰 심사 시작 1~2일 전에 설정하고 심사 종료 후에는 해제한다.

## 7. 인수인계 (전달 사항)

- 화면이 기대하는 최종 JSON 구조는 `result_schema.json`과 `mock_recommendations.json`을 그대로 따른다. 실제 결과에서 구조가 달라지는 부분이 있다면 사전에 공유가 필요하다.
- 브랜드별 `area_id`는 DATA-01/DATA-02가 쓰는 실제 서울시 상권 코드 체계로 통일되어야 지도·경쟁 브랜드 정보가 정상 연결된다.
- 적합도 등급 구간(80/65점)은 실제 점수 분포 확인 후 매우적합/적합/검토 필요 등의 조정이 필요할 수 있다.
